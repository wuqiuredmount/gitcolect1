# 项目上下文续接

本工作区使用**外置记忆文件**对抗会话长度限制与会话中断。

## 核心规则

**开始任何本项目任务前，第一步必须读取：**

    .agents/PROJECT_MEMO.md

这一份文件包含：项目概况、协作硬性约定、已完成功能、数据现状、踩过的坑、待办清单。读完即恢复完整上下文，无需用户复述背景。

## 工作流

1. 读取 `.agents/PROJECT_MEMO.md`。
2. 若 MEMO 提到相关 skill（如 `ai-import-geo-markers`、`ai-recycle-bin-ops`），按需读取对应 `SKILL.md`；通用验证命令见 `.agents/references/common-verification.md`。
3. 按 MEMO 第二节「协作硬性约定」执行任务。
4. 任务涉及代码修改时，同时遵守 `.agents/skills/代码修改返还完整代码/SKILL.md`。
5. 本轮对话结束前，更新 MEMO 的「四、数据现状」与「六、待办」；若发现新坑，补进「五」。

## Token 分层（勿破坏）

- Cline 侧常驻规则只有 `.clinerules/00-index.md`，它是薄索引，不要往里面堆正文。
- 大段流程写在 `.agents/` 里，按需 read_file 加载。
- 同一约定不要在多处重复；重复即双份计费。

## 为什么这样做

DeepSeek 网页版上下文有限，长对话会卡顿或中断。把关键信息写进工作区文件，对话断了也无损；约定与踩坑留在文件里，不依赖 AI 记忆力。

## 维护要点

- MEMO 是**唯一权威记忆**，不要另建同类文件。
- 每次完成实质工作后立即更新，不要攒着。
- 更新时保持结构不变，只改内容，便于下次快速定位。
- 数据现状要写**具体数字**（如「5A 级景区 366 条」），不写模糊描述。
- 若存在赛事 / 活动等时间敏感分组，同时记录其时间字段是否已填齐。

## 验证

- `.agents/PROJECT_MEMO.md` 存在且非空。
- 更新后确认「最后更新」日期已刷新。
