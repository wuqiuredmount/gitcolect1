# AI 批量导入地图标注

把一份批量点位清单，经 AI 联网采集后，变成地图上的蓝色标记 + 富文本文档 + 外链图片。全程不需要人工逐条录入。

## 触发场景

- 用户要把批量清单（景区 / 点位 / 设施 / 门店）变成地图标记
- 用户要求 AI 联网采集信息并导入应用
- 用户要把已有导入流程扩展到新类别（如 5A → 4A）
- 用户提到「AI 批量导入」「自动标注」「批量定位」

## 架构位置（本工作区）

- 导入器：`src/groups/geo/utils/aiImporter.js`
- 导入面板：`src/components/tools/geo/panels/AiImportPanel.vue`
- 数据投放目录：`public/ai-import/`
- 序号发号：`src/groups/geo/utils/systemStore.js` 的 `reserveSequence`
- 增量写入：`src/groups/geo/utils/annotationStore.js` 的 `appendLayers`
- 文档批量写：`src/groups/geo/utils/documentStore.js` 的 `saveDocumentsBatch`
- 编号规则：`src/groups/geo/utils/toolRegistry.js` 的 `formatGraphicId`

## 数据格式（AI 与应用之间的唯一契约）

顶层字段：

- `batchName`：批次名称，如「全国5A级景区 · 第一批」
- `group`：分组名，如「5A级景区」
- `markerColor`：标记颜色，默认 `#1890ff` 蓝色
- `items`：数据数组

每个 `item` 字段：

- `name` 必填。点位名称，写入标记标题与文档名称
- `lat` 必填。纬度，-90 到 90
- `lng` 必填。经度，-180 到 180
- `address` 可选。地址，仅作记录，导入不使用
- `intro` 可选。简介正文，支持 HTML 标签。**字数必须落在 100-1000 字之间**，AI 按景区分量自行选择：世界遗产 / 国家级重点 / 知名大景区写 500-1000 字，普通景区写 100-300 字。不足 100 字视为不合格，不要只写一句话。
- `time` 可选但对时间敏感数据必填。时间判断文本，导入时渲染在富文本顶部（格式「时间：xxx」）。见下方「时间判断强制规则」。
- `images` 可选。图片数组，元素为**文本链接（外链 URL 字符串）**，不使用 base64、不下载文件。导入时在富文本末尾插入 img 标签。

## 时间判断强制规则

当分组或单条数据涉及**运动赛会、体育赛事、活动、节庆、展会、演出、会议、评选、季节限定**等任何与时间相关的对象时，AI 必须给出时间判断，写入 `time` 字段。

要求：

1. **有确切日期就用精确时间**，格式如 `2026年11月9日-21日`、`2026年5月16日开赛，8月22日总决赛`。
2. **日期未定或跨期就用大致时间**，格式如 `2026年11月（具体日期待定）`、`每年4-10月`、`2025年10月起升级为全省联赛`。
3. **绝不允许留空或写「未知」**。若确实查不到，给出基于公开信息的最合理判断，并标注依据，如 `约2026年11月（据贵州省体育局公告）`。
4. **周期性活动要写清周期与届次**，如 `第三届，2026年10月1日开幕`。
5. 时间信息同时建议在 `intro` 中呼应一句，便于阅读上下文。

判定时机：采集阶段就要确定时间，不要留到导入后补。


## 工作流

1. 采集。AI 联网获取每个点位的信息：
   - 必须给出精确 `lat` / `lng`，不要只给地址
   - 涉及赛事 / 活动 / 节庆等时间敏感对象时，必须给出 `time` 时间判断（精确或大致，不可留空）
   - `intro` 用结构化 HTML（定位 / 历史 / 布局 / 核心景观 / 文化价值），字数 100-1000 字
   - `images` 用文本链接（外链 URL），Wikimedia 已不可用，改用国内可访问图源或留空
2. 写入 `public/ai-import/<batch-name>.json`，例如 `5a-batch-1.json`。
3. 更新 `public/ai-import/manifest.json`，把新文件名加进数组。
4. 用户在应用的「AI批量导入」面板点「一键导入全部」或「导入选中」。
5. 导入后校验：条数、分组、地图标记、富文本与图片是否正常。

## 硬性约束（补充项，通用约定见 `.clinerules/00-index.md`）

- 坐标必填，由采集阶段给出（导入器不调 geocode）。
- 增量追加，导入不覆盖已有数据。
- 编号由导入器用 `reserveSequence` 统一预留，AI 不要自己编 `EH.xxxxx`。
- 换类别（4A、博物馆等）只换 JSON 文件与 `group`，代码零改动。

## 验证清单

通用检查（JSON 合法性、manifest 一致性、dev server 可达、落盘确认）见 `.agents/references/common-verification.md`。

本技能专属检查：

1. 坐标完整性：确认无 `lat/lng` 缺失或越界。
2. 跨批次查重：按 `name` 去重，避免同一景区重复导入。
3. 时间完整性：若为赛事 / 活动类数据，抽查 `time` 字段是否均已填写且非「未知」。

## 国内源采集（2026-10-06 新增，维基封锁后的唯一可行路径）

维基百科与 Wikimedia 图床被网络封锁，浏览器也无法访问。改用国内源。

### 采集流程

1. navigate_page 打开百度搜索，找官方名单或百科名录。
2. 用 evaluate_script 在 baike.baidu.com 域下批量创建同域 iframe 加载词条，等渲染后读 contentDocument，提取：
   - 坐标：正则匹配渲染后 HTML 中的 api.map.baidu.com/marker?location=LAT,LNG
   - 名称：h1 或 title
   - 简介：词条摘要区文本
3. 每批 iframe 5-10 家，间隔约 600ms，避免超时。
4. 结果写入 public/ai-import/4a-batch-N.json，登记 manifest。

### 零成本坐标方案

百度百科词条底部内嵌百度地图，含精确坐标。直接正则提取，不调用任何付费接口，不消耗高德额度。这是本项目「高德额度零消耗」约定下的首选坐标来源。

### 关键坑

- fetch 原始 HTML 拿不到坐标（客户端 JS 渲染），必须用 iframe 让页面渲染后再读 contentDocument。
- 同域 iframe 才能读 contentDocument。
- 少数词条结构特殊可能取不到坐标，需单独 navigate 处理。
- 图片源待定：Wikimedia 不可用，暂用百度百科词条图或留空。

### 百度百科内嵌坐标已失效（2026-10-06 实测）

百度百科词条页已不再内嵌 api.map.baidu.com/marker?location=LAT,LNG 形式的精确坐标，只剩按名称跳转的 map.baidu.com/m?word=xxx 标签（无坐标）。上方 iframe 提取流程目前取不到坐标，仅作历史记录保留。

当前可用坐标来源：高德坐标拾取器（lbs.amap.com/tools/picker），人工搜索选中后复制「经度,纬度」（GCJ-02）。Nominatim 在本机不可达，百度/天地图需配 key。

## 查不到坐标时的处理（强制）

涉及位置精确坐标查询、但 AI 检索全网仍查不到可信坐标时：

1. 绝不允许用猜测值、近似值或同名地点的坐标冒充。
2. 把该条信息的 名称、属地、预分组 三项打包写入「待处理未放置信息库」。
   - 数据文件：public/pending-unplaced/pending.json
   - 字段：id（递增编号）、name、region（属地）、group（预分组）、reason（未放置原因）、createdAt
   - UI：顶栏「📥 待处理未放置信息库」按钮，位于「信息数据库」左侧
3. 该条不得进入正式 4a-batch-N.json 与 manifest，等待坐标补全后再转正。
4. 同一景区若在不同来源给出互相矛盾且无法判定的坐标（如平山县景区被解析到北京/邢台），按查不到处理，同样入待处理库。

## 扩展提示

- 新增类别：新建 JSON + 更新 manifest，无需改代码
- 大批量：拆成多个批次文件，每批建议不超过 80 条，导入更稳
