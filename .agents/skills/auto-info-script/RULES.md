## 零、批量调用策略（省「继续」键 · 最高优先级）

> 网页版对话 + 工具调用的固有矛盾：**每次工具调用 = 一轮对话 = 用户按一次「继续」**。
> 本技能执行时的第一原则是——**用尽可能少的工具调用完成尽可能多的事**。

### 0.0 ★ collect 流水线（首选工作流，2026-10-07 新增）

**关键认知**：把「确定性体力活」交给本地脚本，AI 只做「搜索 + 整理草稿」两件脑力活。

    AI：搜索信息 → 整理草稿 JSON（含 name/start/time/intro）
             ↓
    脚本：npm run collect -- build <draft.json>
         自动完成：批量地理编码 → 组装契约 → 写文件 + 更新 manifest + 校验 → 失败入 pending

- **脚本**：`scripts/collect/index.mjs`（零新依赖，复用 data-ops 白名单写入）
- **草稿格式**：`{ group, batchName, markerColor, items: [{ name, start, address?, time, intro, images? }] }`
  - `start` 是**地理编码用地址**，编码成功即转 lat/lng 并从输出移除
  - 缺 `lat/lng` 时自动用 `start`/`address` 编码；仍失败则入 pending，**绝不编造**
- **子命令**：`build <draft.json> [--dry-run]` / `geocode "<地址>"` / `check <file.json>`
- **效果**：单轮采集从 ~6 次往返降到 **~3 次**（写草稿 → 跑 build → 提交）

### 0.1 浏览器采集（仅当 collect 无法覆盖时才用）

- **坐标查询**：一律用页面内 `AMap.PlaceSearch`，**一次 `evaluate_script` 查一批（10-20 个）**。
- **搜索结果读取**：`navigate_page` 超时不要重试，直接 `evaluate_script` 取 `#content_left`。
- **注意**：`AMap.PlaceSearch` 返回 POI，而 `collect` 用高德 geocode（返回地址坐标），二者精度都到 6 位，但口径不同，勿混用。

### 0.2 文件写入

- 优先走 `collect` 流水线（自带 data-ops 备份 + 校验 + manifest 更新）。
- 手工场景：批次与 manifest 合并进**同一条 `execute_command`**。

### 0.3 验证

- `collect` 已内建校验（坐标范围 + time 完整性 + **intro 去标签 ≥100 字**）。
- 额外核对用 `npm run collect -- check public/ai-import/<file>.json`。

### 0.4 提交

- `git add ... ; git commit ...` **一条命令**完成。

### 0.5 目标

- 单轮完整采集（1 分组 / 15-40 条）**压缩到 ≤ 3 次工具调用往返**。

- **背景**：用户希望减少「按继续」次数。
