## 零、批量调用策略（省「继续」键 · 最高优先级）

> 网页版对话 + 工具调用的固有矛盾：**每次工具调用 = 一轮对话 = 用户按一次「继续」**。
> 因此本技能执行时的第一原则是——**用尽可能少的工具调用完成尽可能多的事**。

### 0.1 浏览器采集

- **坐标查询**：一律用页面内 `AMap.PlaceSearch`，**一次 `evaluate_script` 查一批（10-20 个）**。
  - 反例：逐条 fill + click（12 个点 = 24 次调用）
  - 正例：一次批量（1 次调用）
- **搜索结果读取**：`navigate_page` 超时不要重试，直接 `evaluate_script` 取 `#content_left`。
- **多关键词检索**：能用一次搜索拿到就一次拿，不要一个赛事搜一次。

### 0.2 文件写入

- **合并写入**：批次文件与 manifest 用**同一个 `execute_command`**（`;` 串联多条 `data-ops write`）。
- **临时文件一次写**：把 batch、manifest、RULES 临时文件尽量合并写，避免逐个 `write_file`。
- 优先 `execute_command` 跑 `node` 一行脚本完成「生成 + 写入 + 校验」，而非 `write_file` + 命令两步。

### 0.3 验证

- 把「JSON 合法性 + 坐标范围 + 时间完整性 + 简介字数 + manifest 一致性」**合并进一条 `node -e`**。
- **简介字数必须校验**：`i.intro.replace(/<[^>]+>/g,'').length >= 100`（第 2 轮曾出现 7 条不达标）。
- 落盘确认用 `data-ops list`，不与上述校验重复。

### 0.4 提交

- `git add ... ; git commit ...` **一条命令**完成。

### 0.5 目标

- 单轮完整采集（1 分组 / 15-40 条）**压缩到 ≤ 6 次工具调用往返**。
- 若某步必然需要多轮（如依赖上一步返回），才允许拆开；否则一律合并。
