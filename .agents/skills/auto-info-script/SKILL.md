# 自动化信息脚本

## 触发词

**「执行自动化信息脚本」** —— 用户说出这七个字，立即启动本流程。

无需用户补充任何参数。方向、分组、数量全部由 AI 自主决定。

---

## 一、不变规则层（宪法，永不修改）

### 1.1 采集什么

- **可能有价值的** —— 对地理信息标注场景有长期参考意义
- **新奇的** —— 反常识、罕见、首次出现
- **吸引人注意力的** —— 有话题性、值得一看

### 1.2 质量红线（绝不妥协）

- 拒绝虚假信息 —— 无法核实的、传言、旧闻重炒、AI 臆造
- 拒绝垃圾信息 —— 广告、软文、与主题无关、重复条目
- 拒绝政治敏感信息 —— 任何可能引发争议的政治性内容

### 1.3 采集心态

- **鼓励发散思维** —— 不局限于已有分组的线性扩展
- **鼓励创意** —— AI 可以提出全新的分类维度
- **多结合社会热点** —— 当下正在发生、被广泛讨论的事

### 1.4 硬约束（继承项目约定）

- 坐标必须可信；查不到就入 pending-unplaced，**禁止编造**（MEMO 坑#11）
- 写数据文件走 `npm run data-ops`（免审批 + 自动备份）
- 不写 `src/`、不改代码
- 导入到应用需用户在 UI 操作（AI 无法直写 IndexedDB）

### 1.5 量控

- 每轮 **1-3 个分组**
- 每批 **15-40 条**
- 单次采集不超过 **8 轮 crawl**

### 1.6 无确认门

AI 自主决定方向与分组，**不询问用户**。直接执行到「文件已就绪、待用户导入」为止。

## 二、动态规则层（每轮进化）

具体策略（采集维度、命名规范、热点权重、候选方向池）**不写在本文件**，
而是写在同目录的 `RULES.md`，由 AI 每轮执行后主动修改。

> **为什么分两层**：不变规则是「宪法」，保证方向不跑偏；
> 动态规则是「当前策略」，必须随环境（热点变化、已有数据饱和）演化。
> 混在一起的话，改策略就会污染宪法。

**每轮必做**：
1. 执行**前**读 `RULES.md`（承接上轮经验 + 候选方向池）
2. 执行**后**更新 `RULES.md`（记录本轮用了什么、效果如何、下轮建议）
3. 更新 `active-task.md`（长任务实时落盘）

## 三、工作流

### 步骤 0：读现状（防重复）

1. 读 `public/ai-import/manifest.json` —— 已有批次
2. 读 `RULES.md` —— 上轮经验 + 候选方向池
3. 扫现有分组清单（从各 batch 的 group 字段提取）
4. 读 `public/pending-unplaced/pending.json` —— 待处理项

### 步骤 1：定方向（AI 自主决策）

从 `RULES.md` 的「候选方向池」挑选，或结合当下热点自创。选 1-3 个。

**判断标准**：① 范围明确 ② 与已有分组不重复 ③ 有可信来源 ④ 有话题性

### 步骤 2：定分组名

命名公式：`[时间] + [地域] + [类别] + [范围限定]`

- 正例：`2026年1月全国运动赛会`、`成都周边熊猫主题景点`
- 反例：`更多赛事`、`有趣的地方`（边界模糊）

### 步骤 3：联网采集

- 用 edge-devtools（9222 端口）打开搜索引擎 / 官方源
- 逐条核验：名称 + 时间 + 地点 + 坐标 + 简介
- 坐标走高德坐标拾取器（GCJ-02，人工核验口径）
- `intro` 100-1000 字，结构化 HTML
- 时间敏感数据**必填** `time` 字段

### 步骤 4：写文件

命令：npm run data-ops -- write public/ai-import/<batch>.json <tmpfile>

- 格式契约见 skill `ai-import-geo-markers`（**不重复定义**）
- 同步更新 `manifest.json`

### 步骤 5：写报告 + 进化规则

- 在 `RULES.md` 记录本轮：方向 / 条数 / 遇到的坑 / 下轮建议
- 更新候选方向池（划掉已做，补充新的）
- 更新 `active-task.md`
- `git commit`

### 步骤 6：告知用户

一句话说明产出，提示在 UI 导入。

| 做什么 | 用哪个 skill |

| 采集格式、坐标规则、intro 字数 | `ai-import-geo-markers` |
