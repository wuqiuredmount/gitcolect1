# Cline 监控机制（DeepSeek 视角）

> **目的**：DeepSeek 无法直接看到 Cline 的界面/对话流，只能读磁盘。
> 因此需要一套「基于文件的监控机制」，判断 Cline 是否在干活、有没有产出、有没有越界。
> **建立**：2026-10-07　**触发**：派出任务后 / 用户说"它跑完了" / 会话开始

---

## 一、为什么需要监控

**真实教训（2026-10-07）**：
Cline 在界面里显示了一份完整的新报告，但 **`to-deepseek.md` 磁盘上仍是旧版**。
DeepSeek 读文件时**看不到**——因为报告只在 Cline 的对话流里，**没落盘**。

⇒ **判断标准必须基于「磁盘事实」，不是「界面显示」。**

---

## 二、监控五个指标

| # | 指标 | 手段 | 正常 | 异常信号 |
|---|---|---|---|---|
| 1 | **活性**（在跑吗） | Code 进程数 + Cline 任务目录时间戳 | 任务目录近期更新 | 长时间无变化 = 可能卡住 |
| 2 | **产出**（写了吗） | `to-deepseek.md` 时间戳/大小 | 有更新 | 界面说完成但文件没变 = 没落盘 |
| 3 | **越界**（动我的了吗） | `git diff` 检查 `to-cline.md` | 零改动 | 有改动 = 违反排他铁律 |
| 4 | **副作用**（改代码了吗） | `git status` | 与报告一致 | 改了但没报告 = 可疑 |
| 5 | **健康**（API 通吗） | 后端探测（官方API/Chat2API） | 200 | 500/401 = 后端故障 |

---

## 三、监控手段：快照对比法

### 3.1 快照

用脚本 `scripts/watch-cline.mjs` 生成一份「当前状态快照」，存到 `.cache/cline-watch/latest.json`：

    {
      "at": "2026-10-07T22:50:00",
      "toDeepseek": { "mtime": "...", "size": 3214, "lines": 71 },
      "toCline": { "mtime": "...", "size": 2165, "touched": false },
      "git": { "dirty": [], "lastCommit": "f1e85b1" },
      "processes": { "code": 15 },
      "backend": { "ok": true }
    }

### 3.2 对比

再跑一次，与上次快照对比，输出差异：

    npm run watch-cline -- diff

---

## 四、检查时机

| 时机 | 动作 |
|---|---|
| **派出任务后** | 生成基线快照（`npm run watch-cline -- snapshot`） |
| **用户说"它跑完了"** | 对比快照 + 读 mailbox（`npm run watch-cline -- diff`） |
| **会话开始** | 读上次快照，了解断点 |
| **疑似卡住** | 连续两次快照无变化 → 判定卡住 |

---

## 五、异常处理

| 异常 | 判定 | 处理 |
|---|---|---|
| `to-cline.md` 被改 | 违反排他铁律 | 立即报告用户；用 git 恢复；提醒 Cline |
| 界面说完成但 mailbox 没更新 | 未落盘 | 提醒 Cline「报告没写进磁盘」 |
| 代码被改但无报告 | 越界/未汇报 | 读 git diff 核实；要求 Cline 补报告 |
| 后端 500/401 | API 故障 | 重启后端 / 换官方 API |
| 连续两次快照无变化 | 可能卡住 | 报告用户；建议 Cline 重试 |

---

## 六、与 mailbox 协议的关系

- **mailbox** = 通信内容（Cline 写什么）
- **监控** = 通信事实（Cline 有没有写、有没有越界）

**两者互补**：mailbox 靠自觉，监控靠事实核验。

---

## 七、一句话

> **不信任界面，只信任磁盘。**
> 快照 → 对比 → 异常处理，三步闭环。
